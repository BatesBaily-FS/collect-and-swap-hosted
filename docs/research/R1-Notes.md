## Sub-Topic 1 - Currency Exchange

The first challenge that comes to mind with my book exchange app idea is user having to exchange some form of currency. There is a couple ways I could go about this including in-app currency such as points or tokens, Payment Gateways like Paypal, or Mobile payment options through Apple or Android. When it comes to payment process the most important aspect is security, reliability, and simplicity.

- Payment Gateways like PayPal and Shopify are generally considered one of the more popular methods of money processing in web development. This is because gateways provide higher security, supports many payment methods, and simplistic checkout experience. The downsides of this form of payment processing is company transaction fees including fees per transactions between 2.5-3.5% or a monthly fee and integration complexity. (https://www.revolv3.com/resources/pros-and-cons-of-gateway-payment-processing-for-enterprises)

- Using mobile payment options like paying through Apple or Android mobile device is also a popular method of money exchange. This method is popular for its speed and convenience, stronger security, and a more modern approach for money exchange. The main downsides to mobile wallet payments are having to adhere to strict guidelines, higher possibility of technical issues, and accessibility challenges. Customers who use this form of payment on average spend 60% more than those who don't, due to the speed and simplicity of the transaction.

- In-App virtual currency is another option for payment exchange, this would utilize a coin or points system thats users can either purchase or earn though trades. This option is not as popular as the other options mentioned, but could be a better option financially for smaller productions. Considering there would be third-party fees for processing transactions. The downsides to this method are development complexity for currency system, lower built-in security, and user confusion.

## Sub-Topic 2 - User Authentication & Security

When creating an app that has the potential to handle sensitive information ensuring you are using the best practices for user authentication and security is crucial. My focus during this research is finding the best practices and potential services and API's suited for this job.

- Multi-Factor Authentication (MFA) is a highly recommended option for stronger security and authentication, this can involve SMS codes, email verification, and authenticator apps. This is just an extra layer of security to further verify the users identity.

- Services like AuthO offer API's for easily implementing authentication and authorization processes. Utilizing services like this can help simplify security measures and save time in the development stages. There are some downsides to consider including cost that increases as user base grows, difficulty migrating to similar services, and dependency on this service for best performance.

- Common best practices for ensuring proper user authentication and security includes the use of JSON Web Tokens (JWT), strong password policies, session timeouts, and testing user flows. The use of JWT's offer a reliable way to verify users identity, strong password policies would ensure users use unique passwords, implementing session timeouts to protect against unauthorized users, and consistent testing of user flows (registration, login, and logout)to ensure seamless user experience.

## Sub-Topic 3 - API uses

This portion of research is focused on APIs. What they are, how they can be useful, and specific ones that would be useful to implement in my project.

- Application Programming Interfaces (APIs) is a crucial component in web development. APIs allow different softwares applications to communicate seamlessly, allowing developers to integrate various functionalities without having to build from scratch. Saving developers time and effort by making their resources available for integration into applications. There are many APIs available for most tasks including authentication, weather, mapping, payments, and so much more.

- One component of my application that I know an API could be useful for is user authentication and security. By implementing an API, I will be saving myself time in the development rather than having to build this functionality from scratch. An API that I am considering using for this is AuthO, their services offer an API that handles login processes, Multi-Factor Authentication (MFA), and authorization controls. I can set this up to allow users to login in via Google and AuthO will authenticate and authorize users for my app.

- Another component of my app that would benefit from an API, is the location search bar. For this component, I would like to find an geolocation API that can help users locate local bookstores or libraries near them. I am considering Google Places API for taking on this functionality as my users would have access to all of the features of google maps including place details, reviews, and user ratings. The only downside that I have to take into consideration is that once I have exhausted my free credits, I will begin to acquire charges of .17-.50 per request.
